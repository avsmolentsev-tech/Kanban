# Совет директоров (AI Advisory Board) — дизайн

**Дата:** 2026-07-10
**Статус:** дизайн утверждён пользователем, готов к плану реализации

## Суть

Набор ИИ-персон — конкретных реальных личностей из разных областей — с которыми
пользователь обсуждает свои встречи и решения. Персона разбирает прежде всего
**ситуацию/решение** со встречи (сделка, стратегия, развилка), а **людей**
(участников) — как вторую линзу, когда это полезно.

Два режима взаимодействия:
- **One-tap разбор** — на встрече выбираешь персон, каждая даёт структурный разбор.
- **Живой диалог** — чат с персоной (или несколькими), можно спорить и углубляться.

## Что разбирает персона

1. **Ситуация/решение (главное):** бизнес-ситуация, сделка, стратегия, развилка,
   обсуждавшаяся на встрече — мнение, риски, что бы сделал персонаж, вопросы к тебе.
2. **Люди (вторая линза):** участники встречи — переговорный/психологический разбор,
   когда релевантно (связывается с профилями People).

## Данные

- **`advisors`** — `id, name, domain, avatar_url, persona_prompt, voice_style,
  depth ('deep'|'light'), enabled, is_seed, user_id, created_at`. Засеивается ростером
  (seed-персоны общие; пользователь может включать/выключать и позже добавлять свои).
- **`advisor_sessions`** — `id, user_id, meeting_id (nullable — совет можно звать и вне
  встречи), advisor_ids (какие персоны участвуют), created_at`.
- **`advisor_messages`** — `id, session_id, sender ('user'|'advisor'), advisor_id
  (какая персона говорит), content, created_at`.

Всё скоупится по `user_id` (как и весь остальной multi-user).

## Движок персон

- Каждая персона = **системный промпт**, кодирующий её реальную философию, фреймворки,
  стиль решений, характерные формулировки + директиву «оставайся в характере, но давай
  честный практичный совет».
- Персона **«видит» встречу**: транскрипт/резюме подаются в контекст через
  существующие scoped-инструменты (`get_entity_details`, `search_meetings_full`),
  строго по данным пользователя. По желанию — профили участников (People).
- **Анти-выдумки:** персона опирается ТОЛЬКО на реальное содержание встречи; не
  выдумывает факты встречи. Мнение/советы — от лица персонажа, но привязаны к тому,
  что реально обсуждалось.

### One-tap разбор
Для каждой выбранной персоны один вызов LLM → структурный результат:
```
{
  мнение: "оценка ситуации от лица персонажа",
  риски: ["красный флаг 1", ...],
  что_бы_я_сделал: "конкретные шаги",
  вопросы_к_тебе: ["вопрос 1", ...]
}
```
Персоны выполняются **параллельно**. Результат — карточки по персонам.

### Диалог
Чат-тред: сообщения пользователя + ответы персоны, держит контекст встречи + историю.
Несколько персон — отвечают по очереди, могут ссылаться друг на друга («совет заседает»).

## Модель и стоимость

- Совет — там, где качество важнее всего: используем **модель посильнее** (gpt-4.1,
  не mini) для разборов и диалога.
- «Весь совет» = N вызовов → по умолчанию 1-3 персоны; **предупреждение** перед большим
  веером; каждый разбор учитывается в дневном AI-лимите (`checkAiLimit`).

## UI

- **На встрече:** кнопка «Обсудить с советом» → выбор персон (аватары, мультивыбор) →
  карточки-разборы → «продолжить диалогом».
- **Раздел «Совет»:** список персон (карточки: аватар, область), тап — общаешься в любой
  момент (не только про встречу).
- **Управление:** включить/выключить персон; позже — добавление своих.

## Этапы

- **Фаза 1 (этот спек):** таблицы + сид персон (глубокие промпты для ядра, лёгкие для
  остальных) + one-tap разбор на встрече + диалог с одной персоной + раздел «Совет».
- **Фаза 2 (отдельно):** заседание нескольких персон с перекрёстными ссылками, общий
  чат вне встреч, свои персоны, загрузка/генерация аватаров.

## Вне области (пока)

- Кастомные персоны пользователя (Фаза 2).
- Голосовой режим общения с советом.
- Аватары через генерацию/загрузку (Фаза 2; в Фазе 1 — заглушки/инициалы).

## Связано

- Профили людей (телефон/Telegram/фото) — отдельная фича, ляжет во «вторую линзу».
- Диаризация (кто говорил) под GPU — усилит привязку к участникам.
