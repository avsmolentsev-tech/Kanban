# ВКС со стенограммой и задачами — техническое задание

Рабочее название: **Clarity Meet**. Дата: 01.09.2026.

## 1. Зачем

Совещание заканчивается — и через несколько минут в Clarity Space появляется
карточка встречи: стенограмма с указанием, кто что сказал, краткое резюме,
задачи и договорённости с ответственными и сроками. Никто не пишет протокол
руками.

Это отдельный сервис. Clarity Space о нём ничего не знает и не может от него
сломаться — связь только через её публичный API.

### Чего сервис НЕ делает

Перечислено явно, чтобы не расползлось:

- **не записывает видео с камер** — только звук по участникам и демонстрацию
  экрана (обоснование в разделе 6);
- **не собирает общее видео в прямом эфире** — это headless Chrome, около
  четырёх ядер на встречу, при наших ресурсах исключено;
- **не заменяет Clarity Space** — своя база только для комнат и записей,
  задачи и встречи живут там;
- **не делает диаризацию** — она не нужна, см. раздел 5;
- **не поддерживает телефонный вход, трансляции, виртуальные фоны и реакции.**

## 2. Что уже решено

| Решение | Значение |
|---|---|
| Участники | свои пользователи и внешние по ссылке |
| Приоритет первой версии | запись и задачи, а не богатство звонка |
| Запись | звук по дорожкам + демонстрация экрана, камеры не пишем |
| Расшифровка | своя, локальная, на VAD с сохранением таймкодов |
| Размещение | наш сервер Beget, РФ, `31.128.43.174` |
| Данные | не покидают РФ |
| Стек | TypeScript вместо Go, чтобы совпадал с Clarity Space |

**Проверено 01.09.2026:** UDP на порт 7882 снаружи проходит, Beget его не
фильтрует. Три пробных пакета доставлены. Это было главным риском развёртывания.

**Не решено:** сколько одновременных встреч нужно. В ТЗ заложено 1–3 с путём
роста без переписывания. Уточнить до заказа железа.

## 3. Стек

| Слой | Технология | Почему |
|---|---|---|
| Медиа | LiveKit Server (SFU) + LiveKit Egress | открытые, стандарт де-факто |
| Бэкенд | Node + TypeScript + Express, `livekit-server-sdk` | наш стек, общая экспертиза с Clarity Space |
| База | Postgres, отдельная схема в существующем экземпляре | второй экземпляр не нужен |
| Фронтенд | React + Vite + `@livekit/components-react` | наш стек |
| Расшифровка | faster-whisper, свой экземпляр, VAD включён | уже работает в Clarity Space |
| Резюме и задачи | тот же OpenAI-совместимый клиент, что и в Clarity Space | провайдер меняется одной переменной |
| Хранение | диск сервера на старте, S3-совместимое позже | минус контейнер на старте |

**Redis не поднимаем.** В исходном рунбуке он есть, потому что там описан
многоузловой стек. Одноузловой LiveKit, по документации, обходится без него —
проверить при развёртывании, и если ошибка, добавить.

## 4. Архитектура

```
Браузер ──WSS сигналинг──► LiveKit SFU ◄──WebRTC медиа (UDP 7882)── Браузер
   │                            │
   │ HTTPS                      │ вебхуки на внутренний адрес
   ▼                            ▼
Clarity Meet API ◄──────────────┘
   │  комнаты, токены входа, оркестрация записи
   ├──► Egress ──► дорожки на диск
   ├──► Очередь обработки (Postgres)
   │       ├─ VAD + расшифровка по дорожкам
   │       ├─ сшивка в диалог по таймкодам
   │       ├─ обезличивание
   │       └─ резюме и задачи через LLM
   └──► Clarity Space API (Bearer cs_...) ──► карточка встречи, задачи
```

Ключевое соглашение: **идентификатор комнаты один и тот же** в LiveKit, в нашей
базе и в путях к файлам записи. Переименование в одном месте рвёт связь записи
со встречей.

## 5. Расшифровка — почему по дорожкам и с VAD

**По дорожкам, а не общим миксом.** У каждого участника своя аудиодорожка,
каждая распознаётся отдельно. Привязка реплики к человеку получается из самого
факта «это его дорожка» — диаризация не нужна вовсе. Крупные онлайн-сервисы
диаризуют общий микс и ошибаются на похожих голосах и перебивках; здесь
ошибаться нечему.

**VAD вместо обрезки тишины.** Наивно каждая дорожка длится всю встречу, и
распознавание молчания сожгло бы кратно больше ресурсов: пятеро по часу — пять
часов звука при часе реальной речи.

Обрезать тишину заранее, как сделано в Clarity Space, здесь **нельзя**: обрезка
сдвигает время внутри дорожки, и сшить дорожки в диалог по порядку станет
невозможно. Этот дефект уже наступал в Clarity Space — подпись потерянного
фрагмента начала врать ровно по этой причине.

Поэтому: детектор речевой активности находит интервалы речи **с исходными
временами**, распознаётся только речь, таймкоды остаются от оригинала. Даёт
одновременно экономию впятеро и целый таймлайн. В faster-whisper это встроено
(`vad_filter`).

**Что доработать в нашем сервисе транскрипции** (`/opt/transcribe-service`,
исходники у нас): включить `vad_filter` и начать возвращать сегменты с полями
`start` и `end`. Сейчас метод `/transcribe` отдаёт только текст — проверено по
его OpenAPI.

**Экземпляр отдельный.** Существующий общий держит два потока и делит их с
восемью чужими продуктами; дорожки встанут в очередь за чужими задачами.

**Расшифровка идёт после встречи, не в эфире.** Это осознанно: она не нужна
в реальном времени, а разведение по времени с живыми звонками почти вдвое
снижает пиковую нагрузку.

## 6. Запись — почему без камер

Стоимость записи — это процессор во время звонка, а не место на диске.

| Что писать | Цена | Ценность для «встреча → задачи» |
|---|---|---|
| Видео с камеры | ~1 ядро на участника | лица не пересматривают |
| Демонстрация экрана | один готовый поток, собирать не надо | слайды, цифры, документы |
| Звук по участникам | ~0.2 ядра на дорожку | вся стенограмма |
| Общее видео в эфире | ~4 ядра на встречу | не нужно |

Пишем звук и экран. В интерфейсе честно: «записывается звук и демонстрация
экрана». Живой звонок полноценный — камеры работают, люди друг друга видят,
их картинка не сохраняется.

Если позже понадобятся лица — добавляется настройкой на отдельной машине.

## 7. Функциональность первой версии

**Комнаты.** Создание из Clarity Space или из самого сервиса. Постоянная
ссылка. Пароль на вход. Зал ожидания: внешний участник ждёт, пока ведущий
впустит. Роль ведущего у создателя.

**Звонок.** Проверка камеры и микрофона до входа. Сетка видео. Демонстрация
экрана с системным звуком. Чат встречи. У ведущего: заглушить участника,
удалить участника, начать и остановить запись.

**Запись.** По умолчанию выключена, включает ведущий. Явный индикатор для всех
участников, что идёт запись — требование прозрачности, не техническое.

**После встречи.** Дорожки → VAD и расшифровка → сшивка в диалог → обезличивание
→ резюме и задачи → отправка в Clarity Space.

**Что видит пользователь в Clarity Space:** карточку встречи с участниками,
стенограммой по репликам, резюме и списком задач с ответственными.

## 8. Связь с Clarity Space

Только через её публичный API, по токену `cs_...`, который выпускается в
Clarity Space и хранится в конфигурации Clarity Meet.

Используем то, что уже построено: OpenAPI-спецификация, API-токены с отзывом,
конверт ответов. Ничего нового в Clarity Space добавлять не требуется —
проверить на этапе проектирования, хватает ли существующих методов для создания
встречи с участниками и задачами.

Направление одностороннее: Clarity Meet пишет в Clarity Space. Обратной
зависимости нет, поэтому отказ Clarity Meet никак не влияет на Clarity Space.

## 9. Ресурсы

**Текущее состояние сервера, замерено 01.09.2026:** 4 ядра, 15 ГБ памяти,
средняя нагрузка 0.26, простой процессора 91%, память занята 9.3 ГБ,
свободно 6.4 ГБ. Восемь продуктов вместе потребляют около десятой части
процессора.

**Оценка на 1–3 встречи в нашей конфигурации:**

| Компонент | Процессор | Память |
|---|---|---|
| LiveKit SFU | ~1–2 | ~1–2 ГБ |
| Egress, звук + экран | ~1–1.5 | ~1–2 ГБ |
| API и обработка | ~0.5 | ~0.5 ГБ |
| Расшифровка (фоном) | 1–2 | ~2–3 ГБ |

**Узкое место — память, не процессор.** Свободно 6.4 ГБ, потребуется 5–8 ГБ.
Впритык.

**План: сначала измерить, потом покупать.** Разворачиваем на текущем железе,
проводим настоящий звонок втроём с записью, снимаем цифры. Апгрейд — по
результату, а не по оценке.

Тарифы Beget для справки: Бизнес 6 ядер / 12 ГБ ~3 600 ₽/мес, Премиум
8 ядер / 16 ГБ ~5 490 ₽/мес. **Текущая конфигурация 4/15 на эту лестницу не
ложится** — при 8 ядрах у них всего 16 ГБ, то есть памяти почти не прибавится.
Проверить в панели, какие пути расширения есть у конкретного сервера.

**Изоляция обязательна.** Медиа-стеку и Clarity Space выделить ядра жёстко
через ограничения контейнеров. Видеозвонок чувствителен к задержкам: соседний
процесс, отъевший ядро на десять секунд, даёт заикание звука у всех.

## 10. Безопасность и персональные данные

- Всё в РФ: сервер Beget, расшифровка локальная, записи на нашем диске.
- Звук не покидает контур — своя расшифровка, без облачного фолбэка.
- Перед отправкой в модель на резюме текст обезличивается модулем из Clarity
  Space (`pii-redact`), таблица соответствия остаётся у нас.
- Провайдер модели переключается на российского одной переменной.
- Внешние участники входят по ссылке с паролем и через зал ожидания; ссылка
  не даёт доступа ни к чему, кроме своей комнаты.
- Записи и стенограммы доступны только участникам встречи и создателю комнаты.
- Индикатор записи виден всем участникам всё время записи.

## 11. Грабли из исходного рунбука — учесть с первого дня

Каждая стоила кому-то отладки:

1. **Один мультиплексированный UDP-порт, а не диапазон.** Каждый egress входит
   в комнату как участник; на диапазоне подписки отваливаются по таймауту.
2. **`use_external_ip: true`** — иначе SFU анонсирует внутренний адрес и медиа
   не устанавливается.
3. **Вебхуки LiveKit — только на внутренний адрес**, не через публичный домен.
4. **Websocket Support на прокси сигналинга.** Без него звонок «почти работает»:
   интерфейс есть, участники друг друга не видят.
5. **ffmpeg обязателен в рантайм-образе.**
6. **Язык распознавания задавать явно**, иначе русская дорожка определяется как
   английская и фильтр галлюцинаций выбрасывает результат.
7. **Модель обязана возвращать таймкоды по сегментам** — без них речь не
   разложить по спикерам.
8. **Память воркера рендера** — ffmpeg доходит до 4–5 ГБ, лимит в 4 даёт OOM
   посреди сборки.
9. **`shm_size` и capability для egress** — относится к общей сборке через
   headless Chrome. В нашей конфигурации записи по дорожкам Chrome не
   участвует, поэтому пункт не про нас — но он же означает, что памяти
   egress понадобится меньше оценочного. Проверить на этапе 3 и уточнить
   оценку в разделе 9. Если когда-нибудь добавим общее видео — пункт оживает.
10. **Ключи LiveKit одинаковые в трёх местах** — SFU, egress, приложение.
    Рассинхрон даёт молчаливый отказ авторизации.
11. **Дев-ключи из репозиториев публичны** — на сервере только свежие.
12. **Публичный URL вшивается в бандл при сборке** — смена домена требует
    пересборки фронтенда.

## 12. Этапы

**Этап 1. Медиа-стек и голый звонок.** LiveKit и egress в докере, TLS-прокси
сигналинга, порты, ключи. Критерий: два браузера с разных машин видят и слышат
друг друга.

**Этап 2. Комнаты и вход.** База, создание комнат, токены входа, пароль, зал
ожидания, роль ведущего. Критерий: внешний участник заходит по ссылке, ведущий
его впускает.

**Этап 3. Запись.** Egress по дорожкам, звук на участника, демонстрация экрана,
файлы на диск, индикатор записи. Критерий: после встречи на диске лежат дорожки
по числу говоривших.

**Этап 4. Расшифровка.** Свой экземпляр faster-whisper с VAD и сегментами,
очередь обработки, сшивка дорожек в диалог. Критерий: стенограмма встречи втроём
с правильными именами и порядком реплик.

**Этап 5. Задачи в Clarity Space.** Обезличивание, резюме, извлечение задач,
отправка по API. Критерий: после встречи в Clarity Space появилась карточка с
задачами.

**Этап 6. Замер и решение по железу.** Настоящий звонок с записью, снятие
показателей, решение об апгрейде.

Этапы 1–3 дают демонстрируемый результат сами по себе. После каждого можно
остановиться.
