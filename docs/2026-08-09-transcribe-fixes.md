# Разбор и починка транскрибации, 9 августа 2026

## С чего началось

Часовая запись встречи расшифровывалась не полностью: две страницы осмысленного
текста, дальше до конца файла «Музыка. Музыка. Музыка».

## Корневая причина

Не обрыв записи, а цепочка:

1. Файл резался на 13 сегментов по 5 минут и уходил в микросервис faster-whisper
   (`transcribe-service`, docker, модель medium, `MAX_CONCURRENCY=2`, общий на все
   проекты сервера).
2. Сервис занят чужой задачей → сегменты вставали в очередь.
3. **У undici, на котором построен глобальный `fetch` в Node, свой `headersTimeout`
   в 300 секунд.** Сегмент ждал дольше — запрос умирал с безликим
   `TypeError: fetch failed`. Стоявший в коде `AbortSignal.timeout(600_000)` не
   спасал: он ограничивает общее время запроса, а не ожидание заголовков, и
   срабатывает позже.
4. Падали все сегменты (плюс ретрай, который вставал в ту же очередь).
5. Код честно откатывался на whisper.cpp с моделью **small** — и уже там рождалась
   петля-галлюцинация.

Подтверждено экспериментом на сервере (изолированный стенд, сервис не трогали):

| Транспорт | Результат при ожидании 320 с |
|---|---|
| `fetch` (undici) | `FAIL после 301с — fetch failed, cause UND_ERR_HEADERS_TIMEOUT` |
| `node:http` | `OK после 320с — текст доехал` |

## Что сделано

### Транспорт (`whisper-local.service.ts`)

- `serviceRequest` переведён с `fetch` на **`node:http`**, multipart собирается
  вручную. Причина выбора: настроить `headersTimeout` можно только через
  `dispatcher`, то есть через пакет `undici`, которого нет в зависимостях. У
  `node:http` скрытого таймаута заголовков нет — временем управляем мы
  (`SEGMENT_TIMEOUT_MS`, 20 минут, таймаут бездействия сокета).
- Пауза 15 секунд перед ретраем сегмента: мгновенный повтор просто занимал место
  в той же пробке.
- Потерянные сегменты помечаются в тексте `[фрагмент N–M мин не распознан]`.
  Молчаливый пропуск читается как «здесь ничего не говорили».
- **Path traversal** через `req.file.originalname` закрыт в пяти местах
  (`safeTmpName`). `path.join('/tmp', 'svc-1-' + '../../../etc/cron.d/x')`
  схлопывается в `/etc/cron.d/x`: первый `..` съедает литеральный сегмент
  `svc-1-..`, остальные выводят за пределы `/tmp`, и буфер писался (а в `finally`
  удалялся) по произвольному пути.

### Полнота конспекта и задач (`claude.service.ts`)

Час резался в трёх местах, не в одном:

- `transcript.slice(0, 30000)` → `300000`. 30 000 символов — это ~30 минут речи.
- `max_tokens: 8192` на выходе: подробный конспект часовой встречи упирался в
  потолок и обрывался на полуслове вместе с задачами из концовки. `chat()` получил
  параметр `maxTokens`, конспект/Q&A/задачи идут с 16384 (у gpt-4.1-mini потолок
  вывода 32768). **По умолчанию осталось 8192 — остальные вызовы не тронуты.**
- `notes.slice(0, 10000)` / `qa.slice(0, 10000)` **перед извлечением задач** —
  примерно две трети конспекта, задачи из последней части в запрос не попадали.
  Поднято до 60 000.
- `finish_reason === 'length'` больше не проходит молча — пишется предупреждение.

### Маршрутизация (`routes/meetings.ts`)

`processAudioInBackground` шёл сначала в **платный** OpenAI whisper-1 (при наличии
ключа и размере ≤ 24 МБ), а бесплатный локальный бэкенд стоял лишь фолбэком. Через
Telegram-бота тот же файл шёл локально — маршруты вели себя по-разному.

Порядок развёрнут: сначала `transcribeLocal` (он сам предпочитает микросервис и
откатывается на whisper.cpp), облако — только если локально совсем никак. Уход в
платный бэкенд явно логируется. Лимит 24 МБ остался только на облачной ветке.

### Telegram Mini App (`lib/telegram.ts`, `ui/SlidePanel.tsx`)

- **Кнопка «назад».** Панели (встреча, транскрипт, задача…) закрывались только
  маленьким серым «×» — его не находили и закрывали приложение целиком. Теперь,
  пока панель открыта, в шапке Telegram видна нативная кнопка «назад»; она же
  ловит системный жест «назад» на Android. Обработчики лежат стопкой: панели
  вкладываются друг в друга (встреча внутри проекта), «назад» закрывает верхнюю.
- **`disableVerticalSwipes()`** (Bot API 7.7+): Telegram больше не утаскивает окно
  вниз, когда листаешь длинный транскрипт. На старых клиентах метода нет —
  поведение прежнее.

Обе правки активны только внутри Telegram, вне его ничего не меняется.

## Стоимость

Расшифровка — 0, целиком на своём сервере. Разбор часовой встречи
(gpt-4.1-mini): 26 958 входных + 4 164 выходных токенов ≈ **$0,017**.

Для сравнения: тот же час через OpenAI whisper-1 стоил бы $0,36 — в двадцать раз
дороже всего разбора. Именно это убрано из веб-пути.

Подъём лимита вывода до 16384 на практике не удорожает разбор: фактический выход
был 1 549 и 1 856 токенов, далеко и от нового потолка, и от старого.

## Что важно знать дальше

- **Прод живёт на ветке `security-fixes`, а не `master`.** `master` — отдельная
  линия от 1 июля с работой по miniapp/forge, транскрибации там нет. Ветки
  разошлись, стоит свести.
- **Локальное дерево `/root/projects/Kanban` устарело** и не содержит архитектуры
  с микросервисом. Сверяться нужно с сервером или свежим клоном.
- `apps/web/dist` в git не отслеживается — фронтенд собирается на сервере.
- API слушает порт **3002** (3001 занят соседним приложением).
- Ветка OpenAI whisper-1 **не пишет в `usage_logs`**, поэтому по этой таблице
  нельзя доказать отсутствие платных расшифровок — только по логам PM2.

## Живучесть задач (добавлено вечером)

Днём выкатка убила 40-минутную запись на середине: задача жила только в памяти
процесса, `pm2 delete` оборвал её, `processing_status` навсегда остался
`transcribing`, пользователь ждал два часа впустую. Аудио уцелело в `/tmp`
случайно — только потому, что обработчик очистки при убийстве процесса не
отработал.

Теперь:

- `services/pending-jobs.ts` — аудио кладётся на диск (`data/pending-jobs/`) и
  регистрируется в таблице `pending_jobs` **до** начала обработки. Таблицу создаёт
  сам модуль: `schema.sql` в SQLite-диалекте, а база — Postgres.
- При старте API незавершённые задачи возобновляются (`resumeInterruptedTranscriptions`
  в `meetings.ts`, вызов из `index.ts` после `listen`, асинхронно).
- Веб-встречи возобновляются полностью. Телеграмные — тоже: `buildAndSendDraft`
  берёт от `ctx` только `reply`, поэтому подменяем его отправкой в тот же чат и
  выдаём обычную карточку драфта.
- Если аудио не сохранилось или попытки исчерпаны (лимит 2) — задача закрывается
  с явным сообщением пользователю. Молча не пропадает никогда.
- Сбой регистрации не мешает расшифровке: это страховка, а не условие работы.

**Перед перезапуском прода проверять активные задачи:**

```bash
docker stats transcribe-service --no-stream --format "CPU={{.CPUPerc}}"
tail -3 /root/.pm2/logs/kanban-api-out.log
# и встречи в статусе, отличном от done/failed
```

## Незакрытое

- Общего таймаута на job в `whisper-queue.ts` нет: заклинивший часовой файл может
  держать слот очереди до ~5 часов.
- Восстановление после перезапуска не покрывает шаг генерации конспекта: если
  процесс умрёт между расшифровкой и конспектом, задача уже закрыта.
- `boostAudio` в `whisper-queue.ts` именует временные файлы только по `Date.now()`
  — две задачи в одну миллисекунду затрут файлы друг друга.
- Нарезка идёт без перекрытия: на каждой границе сегмента может коверкаться слово.
- Диск сервера занят на 92%.
