# Clarity Meet — медиа-стек и эксплуатация

Сервис видеовстреч со стенограммой и задачами. Живёт отдельно от Clarity
Space и связан с ней только по её публичному API — отказ одного не роняет
другое.

ТЗ: `docs/superpowers/specs/2026-09-01-vks-conference-design.md`

## Что где

| | |
|---|---|
| Медиа-стек | `/opt/clarity-meet/` на `31.128.43.174` — docker compose |
| Сервис комнат | `/opt/clarity-meet/meet-api/` — PM2, процесс `meet-api`, порт 127.0.0.1:7890 |
| Интерфейс | `/var/www/clarity-meet/dist/` — статика, раздаёт nginx |
| Записи | `/opt/clarity-meet/recordings/` — владелец uid 1001, права 775 |
| Комнаты | `/opt/clarity-meet/meet-api/rooms.json` — названия, хеши паролей, участники |
| Секреты | `/opt/clarity-meet/.env` и `/opt/clarity-meet/meet-api/.env`, права 600 |
| Домены | `meet.clarity-space.ru` — интерфейс, `livekit.clarity-space.ru` — сигналинг |

Наружу открыты только `7881/tcp` и `7882/udp` — медиа. Сигналинг и API
слушают localhost, их проксирует nginx с TLS.

## Развернуть с нуля

```bash
mkdir -p /opt/clarity-meet/recordings
cd /opt/clarity-meet

# Ключи LiveKit. Одна пара на SFU и egress — рассинхрон даёт молчаливый
# отказ авторизации без внятной ошибки в логе.
docker run --rm livekit/livekit-server:v1.13.6 generate-keys

# .env по образцу infra/clarity-meet/.env.example, плюс пароль Redis:
#   openssl rand -hex 24
chmod 600 .env

docker compose up -d
```

Redis обязателен. SFU без него работает, а **egress падает с segfault** в
`NewRedisMessageBus` — он использует Redis как транспорт psrpc.

Буфер UDP на хосте должен быть поднят, иначе LiveKit ругается и теряет
пакеты под нагрузкой:

```
net.core.rmem_max=5000000
net.core.wmem_max=5000000
```

## Проверить

```bash
./scripts/meet-smoke.sh
```

Проверяет содержимое ответов, а не только коды: SPA отвечает 200 и HTML на
любой путь, поэтому проверка «код 200» бывает зелёной при полностью неверной
маршрутизации.

## Записать встречу

Скрипты в `infra/clarity-meet/scripts/`, на сервере лежат в `/opt/clarity-meet/`.
Запускать из `/var/www/kanban-app/packages/api` — оттуда доступен `jsonwebtoken`.

```bash
node /opt/clarity-meet/lk-rooms.mjs                 # кто сейчас в комнатах
node /opt/clarity-meet/lk-record.mjs <комната>      # начать запись аудиодорожек
node /opt/clarity-meet/lk-stop.mjs                  # остановить все записи
```

Файл появляется **только после остановки** — egress дописывает его при
завершении. Пока запись идёт, каталог пуст, и это нормально.

Дальше расшифровка и отправка в Clarity Space:

```bash
curl -X POST http://127.0.0.1:7890/api/rooms/<комната>/transcribe \
  -H 'Content-Type: application/json' -d '{"servicePassword":"..."}'
```

Повторный вызов не создаёт вторую карточку встречи: идентификатор уже
отправленной хранится в `rooms.json`.

## Когда что-то не работает

**Участники не видят друг друга, интерфейс при этом поднялся.** Нет
`proxy_set_header Upgrade` / `Connection "upgrade"` в конфиге nginx для
сигналинга. Сигнальный WebSocket не апгрейдится.

**Медиа не устанавливается вовсе.** Проверить `use_external_ip: true` в
`livekit.yaml` и в логе строку `using external IPs` с публичным адресом. Без
этого SFU анонсирует внутренний адрес контейнера.

**Запись рапортует успех, файла нет.** Права на `recordings`. Контейнер
работает от uid 1001; в compose стоит `user: "1001:0"`, но если каталог
создавался вручную — проверить владельца. Признак в логе egress:
`Local upload failed: ... permission denied`, при этом статус задачи
`egress_complete` с кодом 0.

**`unauthorized` в логе egress.** Ключи LiveKit различаются между SFU и
egress. Они обязаны совпадать.

**Расшифровка возвращает пустую стенограмму.** Смотреть `no_speech` и
`speech_duration` в ответе сервиса расшифровки. Пустой результат при
`no_speech: true` — это выключенный микрофон, а не поломка. Проверить уровень:
`ffmpeg -i файл -af volumedetect -f null -`; речь это примерно −20…−30 дБ,
−60 дБ и ниже означает тишину.

**Все дорожки упали.** Эндпоинт расшифровки отдаёт `502`, а не пустой
результат с кодом 200 — это сделано намеренно, чтобы отказ не выглядел как
«на встрече молчали».

## Ресурсы

Замер в простое: весь стек около 38 МБ памяти — LiveKit 17, egress 15,
Redis 5. Лимиты: SFU 2 ядра / 2 ГБ, egress 1.5 ядра / 2 ГБ, Redis 0.3 / 128 МБ.

Лимит egress в 1.5 ядра **специально** ниже стоимости общей сборки видео
(4.0) — egress сам отказывается от таких задач. Поднимать лимит, не понимая
этого, значит открыть дорогу задачам по четыре ядра на встречу.

Машина общая с Clarity Space и восемью чужими продуктами. Расшифровку лучше
не запускать во время живого звонка: faster-whisper на CPU заметно шумит.

## Чего пока нет

Зала ожидания, роли ведущего, кнопки записи в интерфейсе (запись стартует
скриптом), записи демонстрации экрана, автоматической очистки записей и
комнат. Записи копятся на диске бессрочно — это вопрос 152-ФЗ раньше, чем
вопрос места.
